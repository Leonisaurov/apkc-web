apkc studio

Genera un proyecto de app de verdad para apkc (sin Gradle), te da los comandos, traduce lo que apkc responde y anota en qué paso te atascaste. Y desde la sección 2 compila aquí dentro: build --linker go --compiler go enlaza los recursos, saca el .class de tu fuente, lo dexa y firma sin levantar ningún proceso, con apkc.wasm y el proyecto en OPFS, sin server ni conexión. Lo que sigue sin poder hacerse es el build de siempre: aapt2, javac y d8 son programas externos y js/wasm no tiene fork/exec; el botón «intentar compilar» lo muestra tal cual.

      compilar el proyecto aquí dentro (apkc build, sin procesos)
      

        apkc build --linker go --compiler go hace las cuatro cosas con este mismo binario:
        enlaza los recursos, compila MainActivity.java a .class, dexa y firma. No
        arranca aapt2, javac ni d8, así que ocurre dentro de la
        pestaña. Pide dos ficheros tuyos, y ninguno sale de aquí: el android.jar del SDK (la
        única versión medida es la del API 34) y un keystore para firmar. El jar son ~26 MB y se guardan en
        OPFS: se elige una vez y sobrevive a recargar.
